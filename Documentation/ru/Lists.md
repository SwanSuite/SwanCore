# Архитектурная спецификация контейнера List в SwanCore

## Обзор

Контейнер `List<T, Lock>` в `SwanCore` представляет собой высокопроизводительный, потокобезопасный, симметричный двусвязный список, построенный целиком на модульной композиции протоколов. Благодаря строгому разделению топологии ссылок и полезной нагрузки, он обеспечивает мутации границ за константное время **O(1)**, поддерживает обход элементов по стратегии **Lock Dropping** и легко адаптируется под профили синхронизации с нулевой стоимостью.

---

## Мнемоника L-образной формы (География потоков данных)

Чтобы объединить вертикальную природу **Стека** (LIFO) и горизонтальную природу **Очереди** (FIFO) в рамках единой унифицированной структуры данных, в данном фреймворке вводится геометрическая **L-образная метафора**.

Буква **L** служит пространственным якорем в памяти, определяя строгую двумерную географию движения данных.

```text
       [ Head / Peak ]   <--- Вертикальная ось (Стек)
              |               Элементы падают сверху:
              +> [Item]       - Каскадный push: `30 +> 20 +> list`
              |               - Извлечение с головы: `^list`
              |
              |
              |
              +—————————————————— [ Tail / End ]   <--- Горизонтальная ось (Очередь)
                                         <+ [Item]      Элементы пришиваются справа:
                                                        - Каскадный add: `list <+ 10 <+ 20`
                                                        - Извлечение с хвоста: `list^`
```

### 1. Вертикальная ось: Head (Вершина стека)
Самая верхняя вершина буквы **L** представляет собой голову (**Head**) коллекции. Она функционирует как классическая стопка документов, где самый доступный элемент находится на самой вершине.
* **`+>` (Push / Вставка вперед)**: Данные падают вертикально в начало. Правая ассоциативность оператора позволяет выстраивать интуитивный синтаксис наслоения (`30 +> 20 +> list` означает, что сначала ляжет `20`, а `30` упадет прямо поверх него).
* **`^list` (Префиксный Pop)**: Вертикальный «крюк», который подцепляет и снимает верхний элемент с вершины.

### 2. Горизонтальная ось: Tail (Конец очереди)
Нижний правый вектор буквы **L** представляет собой хвост (**Tail**) коллекции. Он работает как стандартная живая очередь, где новые данные всегда прибывают и пристраиваются в самый конец.
* **`<+` / `++` (Add / Append / Вставка назад)**: Данные прикрепляются горизонтально к правому хвосту. Левая ассоциативность оператора формирует непрерывный конвейерный поток данных (`list <+ 10 <+ 20`).
* **`list^` (Постфиксный Pop хвоста)**: Горизонтальный «крюк», который отламывает и забирает самый последний элемент с хвоста.

### Примечание о приоритетах операторов
В языке Swift **постфиксные операторы всегда имеют более высокий приоритет, чем префиксные**.
Если вы примените оба крюка к одному списку без использования круглых скобок (например, `^list^`), компилятор строго в первую очередь вычислит **постфиксный оператор хвоста**, забрав элемент сзади до того, как сработает префиксная операция на голове.

## 1. Композиция и декомпозиция архитектуры

### Схема связей протоколов
Контейнер `List` реализует потокобезопасность и управление топологией за счет комбинации легковесных, изолированных компонентов:

```text
              ┌──────────────────────────────────────┐
              │           ListContainer              │
              └──────────────────────────────────────┘
                  │              │               │
  ┌───────────────▼────────┐ ┌───▼───────────┐ ┌─▼──────────────────────┐
  │ FrontModifiable        │ │ ElementRemover│ │ ListIterator           │
  │ (pushFront / popFront) │ │ (O(1) remove) │ │ (Lock Dropping forEach)│
  └────────────────────────┘ └───────────────┘ └────────────────────────┘
                  │              │               │
                  └──────────────┼───────────────┘
                                 │
                     ┌───────────▼───────────┐
                     │       HasRWLock       │
                     │  (associatedtype Lock)│
                     └───────────────────────┘
```

* **`HasHead` / `HasTail` / `HasCount`**: Предоставляют унифицированные низкоуровневые макетные зацепы для чтения/записи краев последовательности (`Element?`) и управления метриками объема коллекции (`UInt`) в рамках строгой ссылочной семантики.
* **`ObjectContainer`**: Абстрагирует модель хранения памяти, отделяя инфраструктурные обертки (ноды) от прикладного уровня полезной нагрузки. Это позволяет списку `List` удерживать объекты сильными ссылками напрямую, но одновременно позволяет `WeakList` безболезненно осуществлять ленивую очистку нулевых элементов, просто подставив в `Element.T` неявный опциональный тип.

## 2. Ключевые функциональные механизмы

### Симметричные мутаторы границ за O(1)
Вставка и удаление элементов с обоих концов контейнера выполняются за константное время (**O(1)**). Архитектура использует статическую маршрутизацию расширений, завязанную на условные требования к трейтам, для синтеза детерминированного потокобезопасного кода:

```swift
// Фрагмент дефолтной реализации из трейта FrontAppendable
lock.writeLock()
if tail == nil { tail = element }
element.next = head
head?.prev = element
head = element
count += 1
lock.unlock()
```

### Удаление произвольного узла за O(1) (`ElementRemover`)
Исключение элемента из середины списка полностью избавлено от линейного перебора коллекции. При наличии прямой ссылки на элемент структуры, метод `remove(_:)` изолирует узел, сшивает его левого и правого соседей напрямую под защитой эксклюзивного лока записи и декрементирует счетчик, вообще не затрагивая остальные сегменты цепи.

```swift
public func remove(_ element: Element) {
    lock.writeLock()
    if let prev = element.prev { prev.next = element.next } else { head = element.next }
    if let next = element.next { next.prev = element.prev } else { tail = element.prev }
    count -= 1
    lock.unlock()
}
```

### Высококонкурентные итераторы Lock Dropping
Чтобы гарантировать экстремальную отзывчивость системы и исключить взаимные блокировки потоков, `List` не удерживает лок над коллекцией в течение всего цикла обхода. Базовый цикл `forEachElement` использует реактивную тактику **Lock Dropping** (отпускания лока):

1. **Захват лока чтения**: Фиксирует текущий курсор и заранее буферизирует указатель на следующий шаг (`let next = current.next`).
2. **Сброс лока чтения**: Немедленно отпускает блокировку.
3. **Выполнение кода**: Запускает ленивые inline-проверки обслуживания `maintainance` (например, вырезание занулившихся слабой ссылкой контейнеров в `WeakList`) и выполняет пользовательское замыкание полностью вне лока.
4. **Повторный захват**: Безопасно переходит к ранее забуферизированному шагу под новым коротким локом.

Благодаря этому, если текущий элемент в процессе выполнения пользовательского кода будет параллельно удален или изменен другим потоком, итератор гарантированно не собьется с пути и дойдет до конца структуры.

## 3. Примеры идиоматического использования

### Конвейерное наполнение (Режим очереди / FIFO)
Используйте лево-ассоциативный синтаксический конвейер для непрерывного наполнения коллекции с хвоста:

```swift
let queue = List<String, OSAllocatedUnfairLock>()

// Горизонтальный пайплайн через оператор <+
queue <+ "Первая задача" <+ "Вторая задача" <+ "Третья задача"

// Извлечение элементов в порядке очереди через постфиксный крюк
while let task: String = queue^ {
    print("В работе: \(task)")
}
```

### Наслоение кадров на вершину (Режим стека / LIFO)
Используйте право-ассоциативный вертикальный конвейер для наслоения элементов на голову списка:

```swift
let stack = List<Int, AdaptiveSpinLock<LazyContention>>()

// Вертикальное наслоение через оператор +>
100 +> 200 +> 300 +> stack

// Извлечение кадров из стека через префиксный крюк
while let frame: Int = ^stack {
    print("Вычисление кадра: \(frame)")
}
```

### Динамическое таргетирование границ
В ситуациях, когда целевая граница мутации определяется условиями рантайма, используйте динамическую маршрутизацию через матрицу осей `ModifyTarget`:

```swift
func insert<T>(payload: T, into list: List<T, PosixRWLock>, at target: ModifyTarget) {
    // Автоматически направит выполнение в pushFront либо pushBack
    list.push(payload, target: target)
}
```
