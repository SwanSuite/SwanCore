# Декларативное хранение данных и персистенс

Модуль `SwanCore` предоставляет потокобезопасную, расширяемую абстракцию для сохранения и извлечения данных (Repository Pattern). Она объединяет работу с сырыми байтами `Data`, стандартными `Codable`-моделями и специализированными доменными сущностями `Storable`. Из коробки модуль содержит высокопроизводительные бэкенды для `UserDefaults` и файловой системы (`FileStorage`).

## Системные особенности

* **Изоляция низкоуровневого интерфейса**: Для реализации кастомного провайдера персистенса бэкенду достаточно реализовать три базовых метода работы с байтами: `data(forKey:)`, `save(_:forKey:)` и `removeObject(forKey:)`. Всю дженерик-работу по кодированию и сборке объектов протокол `PersistentStorage` берет на себя.
* **Защита мутабельного состояния от рассинхронизации**: Логика кэширования внутри конвейера хранения вынесена на уровень глобального свойства вычисления данных `data`. Операция сериализации всегда динамически генерирует актуальное бинарное представление, защищая мутабельные модели от рассинхронизации данных в оперативной памяти и на диске.
* **Изоляция пространств имен через составные ключи**: Механизм разрешения свойства `compositeKey` использует рефлексию метатипа (`String(reflecting:)`) и очищает рантайм-мусор компилятора Swift. Это гарантирует генерацию детерминированных ключей вида `Module.Model.ID`, исключая коллизии имен разных типов с одинаковыми идентификаторами.
* **Устойчивость к прерыванию транзакций записи**: Бэкенд `FileStorage` использует атомарную запись файлов на диск (`options: .atomic`). Данный механизм гарантирует целостность файловой структуры, предотвращая её повреждение при внезапном закрытии процесса, падении приложения или полной разрядке аккумулятора устройства.
* **Fluent API сокращения**: Расширения протоколов `Encodable` и `Decodable` позволяют сохранять и загружать модели лаконичными цепочками вызовов напрямую на инстансах типов или статических метатипах.

## Базовое использование и Fluent API

Декларативные методы позволяют абстрагировать вызывающий слой приложения от конкретной реализации подсистемы хранения данных:

```swift
import SwanCore
import Foundation

struct UserProfile: Codable {
    let name: String
}

// 1. Инициализируем атомарное дисковое хранилище в папке Caches
let diskStorage = try FileStorage(.cachesDirectory, path: "UserCache")
let user = UserProfile(name: "Stanislav")

// 2. Сохраняем модель через цепочечный Fluent-метод экземпляра
try user.save(for: "current_user", to: diskStorage)

// 3. Загружаем модель напрямую через статический метод типа
if let loadedUser = try UserProfile.load(id: "current_user", from: diskStorage) {
    print("Пользователь успешно извлечен с диска: \(loadedUser.name)")
}
```

## Доменный персистенс через протокол Storable

Протокол `Storable` декларирует интерфейс персистенса доменных моделей на основе сопоставления идентификаторов. Он инкапсулирует логику жизненного цикла синхронизации данных, избавляя вызывающий код от необходимости явного управления хранилищем.

### Архитектурные особенности

* **Мемоизация бинарного представления**: Глобальный конвейер вычисления свойства `data` проверяет наличие заполненного буфера в свойстве `dataCache` перед выполнением полной операции `serialize()`. Для иммутабельных структур сохранение предвычисленных байт в `dataCache` исключает повторные накладные расходы на кодирование данных.
* **Фильтрация артефактов компилятора**: Статический метод вычисления `compositeKey(_:)` анализирует иерархию типов через рефлексию метатипа (`String(reflecting:)`). Он принудительно отсекает системные суффиксы и префиксы рантайма (например, `(unknown context at $`), генерируемые компилятором при выполнении кода в динамических замыканиях, что гарантирует стабильность строковых идентификаторов.

### Автоматический синтез для Codable-моделей

Если доменная сущность изначально соответствует протоколу `Codable`, `SwanCore` автоматически синтезирует методы десериализации и сериализации данных:

```swift
struct OrderRecord: Storable, Codable {
    let id: String
    let amount: Double
    
    // Опциональный кэш байт (возврат nil активирует живую сериализацию)
    var dataCache: Data? { nil }
}

let storage = try FileStorage()
let order = OrderRecord(id: "order_42", amount: 2500.0)

// Система автоматически вычислит детерминированный составной ключ:
// "SwanCore.OrderRecord.order_42"
try storage.store(order)
```

## Оптимизация конфигурации через UserDefaults Бэкенд

Системная инфраструктура `UserDefaults` нативно соответствует интерфейсу протокола `PersistentStorage`. Поскольку базовый системный фреймворк по умолчанию является потокобезопасным, он полностью отвечает строгим требованиям изоляции данных в модели конкурентности Swift 6.

### Реализация плоской иерархии данных

При обработке доменных сущностей `Storable` данный бэкенд принудительно переопределяет стандартную последовательность сохранения:

* **Сплющивание пространств имен**: Запись данных выполняется по базовому свойству `object.id` сущности вместо её полного составного идентификатора `compositeKey`.
* **Чистота конфигурационного файла**: Такой подход исключает замусоривание пространства ключей внутри файла настроек приложения `.plist`, сохраняя записи конфигурации структурированными и удобными для анализа с помощью отладочных утилит.

```swift
let defaultsStorage = UserDefaults.standard

// Записывает данные в хранилище по чистому ключу "order_42" вместо составного пути
try defaultsStorage.store(order)
```

## Дисковый бэкенд (FileStorage)

`FileStorage` реализует персистенс с привязкой к диску в изолированных путях песочницы приложения (например, `.documentDirectory` или `.cachesDirectory`).

### Профиль конкурентности

Структура помечена как `@unchecked Sendable`. Потокобезопасность в строгих рамках Swift 6 Concurrency обеспечивается полной неизменяемостью её основных свойств (`url` и `fileManager`) в сочетании с атомарными свойствами низкоуровневых операций с файлами POSIX, управляемых ядром ОС.

### Особенности работы механизма

* **Упреждающая валидация директорий**: Инициализатор проверяет доступность пути сразу при выделении памяти, принудительно создавая иерархию промежуточных папок через `fileManager.createDirectory`. Эта последовательность гарантирует существование инфраструктуры подкаталогов до начала любых операций чтения или записи.
* **Нулевые накладные расходы на вычисление путей**: Внутренний приватный метод, сопоставляющий строковые ключи с конкретными URL-адресами файлов на диске, снабжен аннотацией `@inline(__always)`. Это исключает создание лишних фреймов в стеке вызовов при частых операциях ввода-вывода.
