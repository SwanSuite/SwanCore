# Утилиты Локализации (Localization Utilities)

Элегантный подфреймворк локализации с низким уровнем накладных расходов, разработанный специально для модульной архитектуры.

Он предоставляет быстрый и типизированный доступ к стандартным процессам локализации через расширения `Bundle` и `String`, а также предлагает продвинутый динамический прокси-механизм (не требующий настройки) для переиспользуемых компонентов и общей инфраструктуры.

## Архитектурный обзор

Локализация внутри модульной экосистемы обычно требует ручной передачи экземпляра `Bundle` целевого модуля вниз к базовым утилитам. SwanCore устраняет эту когнитивную нагрузку, разделяя задачи локализации на два уровня:

1. **Явная статическая маршрутизация (высокооптимизированная):** Стандартные методы локализации, расширяющие `Bundle` и `String`, разработанные для высокочастотных операций в рантайме.
2. **Контекстно-зависимая динамическая маршрутизация (без настройки):** Механизм, который анализирует стек вызовов потока во время выполнения, чтобы изолировать конкретный целевой фреймворк, запросивший локализованный контент.

## Базовые API локализации

### Расширение возможностей String

Самый простой способ получить локализованный контент — вызвать явные методы расширения на любом стандартном экземпляре `String`.

#### Поиск в стандартном бандле приложения
Для строк, расположенных внутри вашего основного таргета приложения (`Bundle.main`), используйте быстрое вычисляемое свойство-сокращение:

```swift
let greeting = "welcome_title".localized
```

#### Переопределение кастомных бандлов и таблиц
Если вам нужно запросить альтернативные бандлы фич, кастомные таблицы локализации или предоставить явные резервные (fallback) значения для рантайма:

```swift
let errorMessage = "network_timeout_error".localized(
    .module, 
    value: "A connection timeout occurred.", 
    table: "LocalizableErrors"
)
```

#### Форматирование строк с аргументами
SwanCore поддерживает тиsafety-форматирование строк с использованием вариативных аргументов (`CVarArg`). Он автоматически применяет `Locale.current`, чтобы гарантировать правильное региональное форматирование чисел, дат и символов валют:

```swift
// В файле Localizable.strings: "speed_format" = "Текущая скорость: %.1f км/ч";
let speedLabel = "speed_format".localized(with: 120.5) // Выведет "Текущая скорость: 120.5 km/h" или "Текущая скорость: 120,5 km/h" в зависимости от региона пользователя
```

### Прямое извлечение из Bundle

SwanCore расширяет `Bundle` чистыми фасадами API, поддержкой форматирования и инструментом извлечения сырых отображений строк, разработанным для пайплайнов тестирования, валидации полноты удаленной конфигурации или движков тестирования верстки.

```swift
// Прямой чистый поиск с форматированием аргументов
let message = Bundle.main.localized("items_count_key", value: nil, table: nil, 42, "Folder")

// Синхронное извлечение полной матрицы локализации
do {
    if let localizedDictionary = try Bundle.main.fetchLocalizableStrings() {
        print("Найдено переводов: \(localizedDictionary.count)")
    }
} catch {
    print("Не удалось сериализовать маппинг ресурсов локализации: \(error)")
}
```

## Контекстно-зависимая динамическая локализация

При написании общего кода — такого как кастомные UI-компоненты (дизайн-системы), базовые обертки или общие менеджеры маршрутизации — хардкод `.main` или передача явных бандлов создают много бойлерплейта.

SwanCore вводит вычисляемое свойство `.localizedDynamic` и его параметризованные методы для решения этой проблемы.

```swift
// Внутри общего многомодульного фреймворка фичи/инфраструктуры
public final class CustomHeaderView: UIView {
    private let titleLabel = UILabel()

    public func setupView() {
        // Автоматически разрешается в каталог ресурсов того фреймворка, который содержит CustomHeaderView
        titleLabel.text = "shared_component_header_title".localizedDynamic
    }
}
```

### Форматирование с динамическими аргументами

Движок динамического поиска бесшовно поддерживает вариативные аргументы. Он определяет вызывающий таргет в рантайме и применяет активную системную локаль пользователя для вставки плейсхолдеров:

```swift
// В файле Localizable.strings внутри общего фреймворка: "items_count_label" = "Найдено %d элементов в %@";
let statusText = "items_count_label".localizedDynamic(with: 42, "Storage")
```

### Архитектура под капотом

Динамический поиск полностью обходит традиционные модели подклассирования `Bundle`, чтобы предотвратить циклические блокировки зависимостей во время критических фаз запуска приложения. Вместо этого он взаимодействует с низкоуровневой архитектурой выполнения:

1. Он считывает контекст бэктрейса вызывающего потока с помощью `Thread.callStackReturnAddresses`.
2. Он транслирует последовательность указателей инструкций в изолированный заголовок базы динамического разделяемого объекта (`Dl_info.dli_fbase`).
3. Он использует внутренний `OSAllocatedUnfairLock` для безопасной мемоизации структуры отслеживания "инструкция-в-бандл" без повторного запуска тяжелых итераций по файловой системе или сложных обходов метаданных.

## Инженерные правила и матрица производительности

При выборе между статическими и динамическими эндпоинтами придерживайтесь следующих архитектурных правил:

| API | Нагрузка на производительность | Профиль конкурентности (Concurrency) | Рекомендуемая среда |
| :--- | :--- | :--- | :--- |
| `String.localized`<br>`String.localized(with:)` | **Экстремально низкая** <br> Прямые маппинги указателей при инлайн-компиляции | Потокобезопасность без блокировок (`Sendable`) | Высокочастотные пути рендеринга (`cellForRowAt:`, кастомные циклы отрисовки/отсечения) |
| `String.localizedDynamic`<br>`String.localizedDynamic(with:)` | **Средняя** <br> Накладные расходы на трейсинг потока при промахе кэша; O(1) поиск по карте памяти с блокировкой при попадании | Безопасно для изолированных циклов рантайма в современной конкурентности Swift 6 | Настройки структурной инициализации, дизайн-системы, базовые таргеты без бойлерплейта |

> ⚠️ **Критическое предупреждение:** Никогда не используйте `.localizedDynamic` или `.localizedDynamic(with:)` напрямую внутри высокоитеративных последовательностей рендеринга, циклов источников данных таблиц/коллекций (`cellForRowAt:`) или пайплайнов кастомного лайаута. Для критических к производительности представлений (subviews) разрешайте целевой `Bundle` заранее или кэшируйте локализованные строки на уровне экземпляра класса.
