# Обертка над NSCache (Type-Safe Cache)

Компонент `Cache` предоставляет потокобезопасную, строго типизированную обертку над системным классом `NSCache`, адаптированную под современные требования Swift 6 Strict Concurrency.

## ✨ Ключевые особенности
* **Безопасность типов**: Использование внутреннего адаптера `KeyAdapter` позволяет использовать любые нативные типы Swift, удовлетворяющие протоколу `Hashable`, в качестве ключей (в отличие от оригинального `NSCache`, требующего только `NSObject`).
* **Управление весом (Cost-aware)**: Через протокол `Costable` кэш умеет автоматически подсчитывать «вес» объектов и вытеснять старые элементы при превышении лимита памяти `totalCostLimit`.
* **Перехват вытеснения (Eviction Interceptor)**: Возможность передать `@Sendable` замыкание, которое сработает ровно в момент, когда операционная система решит очистить объект из памяти из-за низкого уровня ресурсов.
* **Готовность к Swift 6**: Класс полностью удовлетворяет требованиям `Sendable`. Внутренний механизм полагается на встроенную атомарную потокобезопасность `NSCache`.

## 🚀 Использование

### 1. Базовое кэширование
Для работы кэша тип `Value` обязан быть классом (`AnyObject`), так как это ограничение базового `NSCache`. Если нужно хранить структуры, оборачивайте их в легкие классы-контейнеры.

```swift
import SwanCore
import Foundation

// Инициализация кэша с логгером вытеснения элементов
let userCache = Cache<Int, NSString>(onWillEvictObject: { evictedUser in
    print("Пользователь удален из кэша памяти: \(evictedUser)")
})

// Настройка лимита по количеству элементов
userCache.countLimit = 2

// Запись через стандартный subscript
userCache[42] = "Stanislav"
userCache[7] = "Alex"

// Чтение данных
if let name = userCache[42] {
    print("Найдено в кэше: \(name)")
}

// Удаление конкретного элемента
userCache[42] = nil

// Полная мгновенная очистка памяти
userCache.clear()
```

## ⚖️ Протокол Costable и физический вес данных

Файл `Costable+Conformances.swift` ретроактивно подписывает базовые типы Swift и Foundation под протокол `Costable`. Это позволяет кэшу автоматически контролировать лимит общего объема занимаемой памяти (`totalCostLimit`) в байтах.

### 📐 Математика дефолтных реализаций:
* **String**: Вес вычисляется по точному количеству UTF-8 байт (`utf8.count`), что корректно учитывает как стандартные ASCII-символы (1 байт), так и сложные Unicode/Emoji символы (до 4 байт).
* **Array**: Вычисляет честный размер непрерывного буфера памяти в байтах, умножая количество элементов на их шаг выравнивания в памяти (`MemoryLayout<Element>.stride`).
* **Dictionary**: Учитывает физический вес нод хэш-таблицы в RAM, складывая шаги выравнивания структуры ключа и значения для каждого заполненного бакета.
* **Data / NSData**: Напрямую возвращает точный объем бинарного буфера в байтах (`count` / `length`).

### 📦 Пример работы с контролем веса:
```swift
// Кэш с лимитом по общему объему памяти в 10 Мегабайт
let heavyDataCache = Cache<String, NSData>()
heavyDataCache.totalCostLimit = 10 * 1024 * 1024

if let fileData = NSData(contentsOf: fileURL) {
    // При записи кэш автоматически прочитает свойство .cost у NSData
    heavyDataCache["cached_file"] = fileData
}
```

> ⚠️ **Важное примечание для ссылочных типов (Классов):**
> Дефолтные реализации для `Array` и `Dictionary` используют `MemoryLayout.stride`. Если внутри коллекции лежат классы, то их `stride` вернет физический размер самих указателей на кучу (по 8 байт на элемент). 
> Если вам нужно кэшировать коллекции тяжелых ссылочных объектов, возвращайте их реальный вес данных в куче, создав собственную явную подписку под протокол `Costable`.
