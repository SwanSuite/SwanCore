# SwanCore Versioning Engine

Высокопроизводительный, эффективный с точки зрения памяти и глубоко расширяемый дженерик-фреймворк для версионирования программного обеспечения, написанный на современном Swift.

 В отличие от традиционных плоских инструментов версионирования, **SwanCore** строго отделяет неизменяемые базовые примитивы индустрии (`major.minor.patch`) от изменчивых, специфичных для конкретного проекта жизненных циклов развертывания (пререлизы, ветки, билды, метаданные CI/CD), используя передовые дженерики Swift и типы безопасных абстрактных деревьев компоновки.

---

## 🚀 Ключевые особенности

- **Базовые примитивы с нулевой аллокацией**: Неизменяемые структурные координаты, поддерживаемые оптимизированными каскадами распределения памяти.
- **Дженерик-контексты жизненного цикла (`VersionStage`)**: Переключайте контексты на этапе компиляции — от чистых релизов (`VoidVersionStage`) до полного Semantic Versioning 2.0.0 (`CanonicalVersionStage`) или полностью кастомных корпоративных конвейеров.
- **Двусторонняя симметрия схем**: Используйте одну и ту же токенизированную строку шаблона как для **форматирования** модели в строку, так и для **парсинга** строки обратно в структурный тип.
- **Строгий компилятор AST на конечных автоматах**: Быстрый линейный сканер потока символов, выполняющий сложные правила проверки вложенности (оценка приоритетов И/ИЛИ) без регулярных выражений и узких мест в производительности.
- **Взаимоисключающие выборки (`select`)**: Нативная поддержка строгого One-Hot выбора альтернативных конвейеров через структурные конфигурации с пайпом (`[ A | B ]`).

## 🛠 Архитектурный обзор

Движок выступает в роли слабосвязанного моста между вашими структурными моделями контейнеров данных и требованиями к представлению макета:

```text
[ Raw String Input ] ──► (VersionFormatter Scanner) ──► [ Token Dictionary ]
                                                                │
                                                         (TokensComposable)
                                                                ▼
[ Stylized Output ]  ◄── (VersionFormatter Engine)  ◄── [ Generic Version<Stage> ]
```

## 📝 Синтаксис шаблонов форматирования

Шаблоны используют специальные маркеры макета в верхнем регистре, перед которыми ставится символ `%`. Все статические знаки препинания (точки, дефисы, скобки, пробелы) обрабатываются как строгие инварианты макета.

### 1. Базовые системные токены фреймворка
- `%MJ` — **Major**: Доминантный первичный целочисленный индекс базовой версии.
- `%MN` — **Minor**: Вторичный индекс итерации улучшения функций.
- `%P`  — **Patch**: Третичный индекс последовательности развертывания исправления дефектов.

### 2. Токены канонической стадии (`CanonicalVersionStage`)
- `%SI` — **Stage Identifier**: Строковое имя промежуточного этапа пререлиза (`alpha`, `beta`, `rc`).
- `%SV` — **Stage Version**: Инкрементальный шаг отслеживания, продвигающийся внутри активного пререлиза.
- `%B`  — **Build**: Низкоуровневый технический маркер последовательности сборки машины.

### 3. Структурные границы условий `[...]`
Квадратные скобки определяют иерархические условные логические слои:
- **Стратегия И (ALL)**: Если опциональный слой напрямую содержит токены шаблона, блок оценивается как активный **только в том случае, если все непосредственные токены макета явно заполнены** не-nil параметрами.
- **Стратегия ИЛИ (ANY)**: Если опциональный слой содержит вложенные подблоки без непосредственных корневых токенов, он делегирует отслеживание активного статуса вниз, сохраняя видимость, если **хотя бы одна** дочерняя ветка остается валидной.

### 4. Фреймворк альтернативного выбора `[ A | B ]`
Оператор пайпа `|` внутри условного уровня разделяет доменное пространство на взаимоисключающие ветки выбора. Рантайм-контроллер применяет **строгие метрики проверки One-Hot**: **ровно одна** альтернативная ветка должна оцениваться как активная. Если 0 или ≥ 2 веток пытаются отрендериться одновременно, обнаруживается конфликт планирования, и весь узел безопасно схлопывается в пустой поток.

## 📦 Базовые профили макетов (Пресеты)

SwanCore предоставляет стандартные встроенные конфигурации макетов через `VersionFormatter`:

| Пресет | Структура шаблона | Пример результирующей строки |
| :--- | :--- | :--- |
| `.short` | `%MJ[.%MN][.%P]` | `"1.2.3"` или `"1"` *(нулевые компоненты на конце усекаются)* |
| `.medium` | `%MJ.%MN[.%P][[-%SI[.%SV]]\|[ b%B]]` | `"1.2.3-rc1"`, `"1.0 b12"` или `"2.0"` *(строгий выбор альтернатив)* |
| `.long` | `version %MJ.%MN.%P[-%SI[.%SV]][ build %B]` | `"version 1.2.3-rc1 build 45"` |
| `.semVer` | `%MJ.%MN.%P[-%SI[.%SV]][+b%B]` | `"1.2.3-rc1+b45"` *(строгое соответствие спецификации SemVer 2.0.0)* |
| `.appleBundle`| `%MJ.%MN.%P` | `"1.2.3"` *(стандартный унифицированный макет для экосистемы Apple)* |

## 💻 Примеры использования

### 1. Базовые модели и форматы
```swift
// Чистый профиль версии без расширений (VoidVersionStage с нулевой аллокацией)
let coreLib = CoreVersion(major: 1, minor: 4, patch: 0, stage: .void)
print(coreLib.formatted(.short)) // Вывод: "1.4"

// Полноценный профиль стандартной SemVer-версии с метаданными
let stage = CanonicalVersionStage(identifier: .beta, version: 3, build: 412)
let appVersion = CanonicalVersion(major: 2, minor: 0, patch: 1, stage: stage)

print(appVersion.formatted(.semVer)) // Вывод: "2.0.1-beta.3+b412"
print(appVersion.formatted(.medium)) // Вывод: "2.0.1-beta.3" (билд опущен из-за конфликта select)
```

### 2. Мощный зеркальный парсинг строк
Благодаря унифицированному протоколу `TokensComposable`, модели могут нативно синтезировать свое состояние из текстовых описаний, соответствующих любой валидной маске форматирования:

```swift
// Прямой парсинг строк через тип-безопасный LosslessStringConvertible (по умолчанию использует .medium)
if let parsed = CanonicalVersion("1.0 b145") {
    print(parsed.major)         // Вывод: 1
    print(parsed.minor)         // Вывод: 0
    print(parsed.stage?.build)  // Вывод: 145
}

// Обратный парсинг по кастомному текстовому шаблону конфигурации
let gitTagFormatter = try VersionFormatter(format: "release-v%MJ.%MN[.%P]")
if let rawTokens = gitTagFormatter.parse("release-v1.8") {
    let customVersion = CanonicalVersion(tokens: rawTokens)
    print(customVersion?.minor) // Вывод: 8
}
```

### 3. Тип-безопасная матрица эволюционной сортировки
```swift
let v1 = CanonicalVersion(major: 1, minor: 0, stage: CanonicalVersionStage(identifier: .alpha, version: 5))
let v2 = CanonicalVersion(major: 1, minor: 0, stage: CanonicalVersionStage(identifier: .releaseCandidate, version: 1))
let v3 = CanonicalVersion(major: 1, minor: 0, stage: CanonicalVersionStage(identifier: .release)) // или nil-стадия

print(v1 < v2)  // Вывод: true  (alpha < rc)
print(v2 < v3)  // Вывод: true  (rc < release/stable)
print(v3 == CanonicalVersion(major: 1, minor: 0, patch: 0)) // Вывод: true (нормализация nil-компонентов)
```

## 🔒 Потокобезопасность и производительность

- **Соответствие `Sendable`**: Все структурные компоненты данных, типы макетов форматов, внутренние состояния абстрактного дерева (`AST.Node`) и контексты валидации строго поддерживают полную совместимость с протоколом `Sendable`.
- **Линейная производительность компиляции**: Сложные операции с шаблонами макетов компилируются строго **один раз** при инициализации движка токенов в легковесные узлы выполнения. Это превращает циклы форматирования и обратного сканирования в высокоскоростные каскады ветвления CPU без аллокаций в куче (heap-free).
