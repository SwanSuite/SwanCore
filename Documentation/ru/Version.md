# Модуль версионирования SwanCore (Data Models & Formatting Helpers)

Компонент предоставляет набор вспомогательных структур данных и инструментов для представления, форматирования и парсинга версий программного обеспечения. Решение разделяет неизменяемые базовые компоненты версии от изменяемых контекстов жизненного цикла развертывания с помощью дженериков Swift и разбора абстрактных деревьев компоновки (AST).

## Архитектура и основные компоненты

Инструмент состоит из трех логических слоев:
1. **Контейнеры данных (`Version<Stage>`)**: Обобщенная структура, инкапсулирующая базовые числовые параметры версии (`major`, `minor`, `patch`) и объект стадии (`Stage`).
2. **Стратегии жизненного цикла (`VersionStage`)**: Протокол для реализации контекстов пре-релизов и сборок. Включает две готовые реализации:
   * `VoidVersionStage` (псевдоним `CoreVersion`) — легковесная структура с нулевым выделением памяти для базовых версий без метаданных.
   * `CanonicalVersionStage` (псевдоним `CanonicalVersion`) — структура для полной поддержки спецификации SemVer 2.0.0.
3. **Движок компиляции макетов (`VersionFormatter`)**: Компилятор строки формата в абстрактное синтаксическое дерево (AST) на этапе инициализации, обеспечивающий двунаправленное преобразование (рендеринг в строку и обратный парсинг строки в токены).

## Синтаксис шаблонов форматирования

Конфигурация макетов `VersionFormatter` описывается строкой шаблона, где символы верхнего регистра после знака `%` интерпретируются как динамические токены. Статические знаки пунктуации, разделители и текст обрабатываются как инварианты макета.

### Идентификаторы токенов
* `%MJ` — **Major**: Индекс главного релиза (компонент `major`).
* `%MN` — **Minor**: Индекс итерации функциональности (компонент `minor`).
* `%P`  — **Patch**: Индекс исправления дефектов (компонент `patch`).
* `%SI` — **Stage Identifier**: Строковое имя пре-релиза (`alpha`, `beta`, `rc` — компонент `stage.identifier`).
* `%SV` — **Stage Version**: Шаг отслеживания внутри пре-релиза (компонент `stage.version`).
* `%B`  — **Build**: Маркер последовательности компиляции сборки (компонент `stage.build`).

### Логические границы `[...]`
Квадратные скобки группируют элементы макета в условные блоки:
* **Стратегия AND (ВСЕ)**: Если блок верхнего уровня содержит токены, он рендерится **только при условии, что все вложенные токены имеют значения, отличные от `nil`**.
* **Стратегия OR (ЛЮБОЙ)**: Если блок содержит исключительно вложенные подблоки (без токенов на своем уровне), он делегирует проверку вниз. Блок остается видимым, если **хотя бы один дочерний элемент признан активным**.

### Альтернативный выбор `[ A | B ]`
Оператор `|` внутри условных границ разделяет область на взаимоисключающие ветви выбора. Среда выполнения применяет **строгие метрики проверки One-Hot**: **ровно один** из альтернативных путей должен быть активным для корректного рендеринга. При обнаружении конфликта (активны 0 или ≥ 2 ветвей) узел полностью скрывается из выходного потока.

## Встроенные профили макетов (Пресеты)

В `VersionFormatter` интегрированы стандартные конфигурации:

| Пресет | Структура шаблона | Пример вывода |
| :--- | :--- | :--- |
| `.short` | `%MJ[.%MN][.%P]` | `"1.2.3"` или `"1"` *(конечные нулевые компоненты опускаются)* |
| `.medium` | `%MJ.%MN[.%P][[-%SI[.%SV]]\|[ b%B]]` | `"1.2.3-rc1"`, `"1.0 b12"` или `"2.0"` *(строгий альтернативный выбор)* |
| `.long` | `version %MJ.%MN.%P[-%SI[.%SV]][ build %B]` | `"version 1.2.3-rc1 build 45"` |
| `.semVer` | `%MJ.%MN.%P[-%SI[.%SV]][+b%B]` | `"1.2.3-rc1+b45"` *(соответствие спецификации SemVer 2.0.0)* |
| `.appleBundle`| `%MJ.%MN.%P` | `"1.2.3"` *(унифицированный макет идентификации App Store / TestFlight)* |

## Примеры использования

### 1. Форматирование моделей данных
```swift
// Использование базовой версии без метаданных (VoidVersionStage)
let coreLib = CoreVersion(major: 1, minor: 4, patch: 0)
print(coreLib.formatted(.short)) // Выведет: "1.4"

// Использование семантической версии (CanonicalVersionStage)
let stage = CanonicalVersionStage(identifier: .beta, version: 3, build: 412)
let appVersion = CanonicalVersion(major: 2, minor: 0, patch: 1, stage: stage)

print(appVersion.formatted(.semVer)) // Выведет: "2.0.1-beta.3+b412"
print(appVersion.formatted(.medium)) // Выведет: "2.0.1-beta.3" (сборка исключена One-Hot селектором)
```

### 2. Двунаправленный парсинг строк
Парсер выполняет декомпозицию текстовой строки на основе скомпилированного синтаксического дерева с поддержкой механизма откатов (rollback) при несовпадении маски:

```swift
// Прямая инициализация из строки через LosslessStringConvertible (использует .medium)
if let parsed = CanonicalVersion("1.0 b145") {
    print(parsed.major)         // Выведет: 1
    print(parsed.minor)         // Выведет: 0
    print(parsed.stage?.build)  // Выведет: 145
}

// Парсинг кастомного строкового формата с извлечением словаря токенов
let gitTagFormatter = try VersionFormatter(format: "release-v%MJ.%MN[.%P]")
if let rawTokens = gitTagFormatter.parse("release-v1.8") {
    let customVersion = CanonicalVersion(tokens: rawTokens)
    print(customVersion?.minor) // Выведет: 8
}
```

### 3. Сортировка и сравнение
Тип `Version` реализует протокол `Comparable`. Сравнение выполняется последовательно по цепочке: `major` -> `minor` -> `patch` -> `stage`.

```swift
let v1 = CanonicalVersion(major: 1, minor: 0, stage: .init(identifier: .alpha, version: 5))
let v2 = CanonicalVersion(major: 1, minor: 0, stage: .init(identifier: .releaseCandidate, version: 1))
let v3 = CanonicalVersion(major: 1, minor: 0, stage: .init(identifier: .release))

print(v1 < v2)  // Выведет: true (alpha < rc)
print(v2 < v3)  // Выведет: true (rc < release/stable)
print(v3 == CanonicalVersion(major: 1, minor: 0, patch: 0)) // Выведет: true (нормализация отсутствующих компонентов)
```

## Потокобезопасность и вычислительная сложность

* **Безопасность типов**: Все типы данных (`Version`, `VersionFormatter`), вложенные перечисления (`AST.Node`) и внутренние структуры данных полностью поддерживают протокол `Sendable`. Это позволяет использовать их в асинхронных контекстах Swift 6 Strict Concurrency без дополнительных примитивов синхронизации.
* **Производительность**: Разбор строки формата и построение дерева AST происходят однократно при инициализации экземпляра `VersionFormatter`. Последующие операции форматирования и обратного парсинга выполняются за линейное время O(N) от длины обрабатываемой строки версии, без использования регулярных выражений и без выделений динамической памяти в куче (heap allocations) для промежуточных узлов.
