# Расширения словарей и RawRepresentable (Dictionary Transformations)

Модуль `SwanCore` предоставляет мощный набор функциональных расширений для стандартного типа `Dictionary`, который упрощает трансформацию хэш-таблиц, маппинг ключей/значений и взаимную конвертацию между доменными перечислениями (`enum: RawRepresentable`) и их сырыми системными типами (`String`, `Int` и т.д.).

## ✨ Ключевые особенности
* **Сквозная функциональная трансформация**: Методы `mapToDictionary` и `compactMapToDictionary` позволяют преобразовывать структуру целиком в один вызов, используя оптимизированные нативные конструкторы Swift.
* **Изолированный маппинг ключей**: Расширения `mapKeys` и `compactMapKeys` дают возможность менять типы и регистры ключей, не затрагивая и не перевыделяя память под полезную нагрузку значений.
* **Автоматическое разрешение представлений (`resolveRepresentation`)**: Набор перегрузок полностью закрывает все возможные комбинации матриц данных, переводя словари из объектных перечислений в сырые структуры для сериализации (и обратно) без написания ручных циклов.
* **Безопасная очистка (Pruning/Sweep)**: При конвертации сырых данных обратно в строго типизированные перечисления, методы `compactMap` автоматически отсекают любые `nil`-значения и битые ноды, которые не смогли инициализироваться.
* **Высокая производительность**: Все методы помечены аннотацией `@inlinable` для инлайнинга кода компилятором на этапе оптимизации сборки.
* **Бескомпромиссная ленивость (Zero-Allocation)**: Метод `lazyCompactMapToDictionary` выполняет трансформацию без выделения промежуточных массивов в куче, стримя данные напрямую в предвыделенную хэш-таблицу.

## 🚀 Функциональный маппинг (Shorthands)

Расширения позволяют уйти от громоздких императивных циклов и промежуточных мутабельных словарей при базовых трансформациях данных:

```swift
import SwanCore

let source = ["one": 1, "skip_me": 2, "three": 3]

// 1. Маппинг всего словаря с фильтрацией nil-нод
let transformed: [String: String] = source.compactMapToDictionary { key, value in
    guard key != "skip_me" else { return nil }
    return (key.uppercased(), String(value * 10))
}
// Результат: ["ONE": "10", "THREE": "30"]

// 2. Трансформация только ключей словаря
let dictWithUpperKeys = source.mapKeys { \$0.uppercased() }
// Результат: ["ONE": 1, "SKIP_ME": 2, "THREE": 3]
```

## 🏎️ Гипер-оптимизированная ленивая трансформация

Для высоконагруженных участков кода, где рантайм-производительность критичнее времени компиляции, доступен метод `lazyCompactMapToDictionary`. Он полностью исключает аллокации временных массивов за счет ленивого стриминга последовательности (`lazy.compactMap`) напрямую в результирующую хэш-таблицу с заранее зарезервированной емкостью (`reserveCapacity`).

```swift
let heavySource: [String: Int] = /* Большой словарь данных */

// Трансформация без промежуточных копий в памяти (Heap Allocations)
let ultraFastResult: [String: String] = heavySource.lazyCompactMapToDictionary { key, value in
    guard value % 2 == 0 else { return nil } // Отсекаем нечетные
    return (key.camelCasedSnake, "Value_\(value)")
}
```

## ⚙️ Управление перечислениями через `resolveRepresentation`

Система `resolveRepresentation` автоматически выводит целевые типы из контекста вызова и выполняет конвертацию регистров и представлений.

### 1. Конвертация из перечислений в сырые типы (Для отправки на Бэкенд/Сериализации)
Позволяет быстро «сбросить» строгие доменные перечисления в сырые строки или числа, готовые для кодирования в JSON:

```swift
enum ResponseKey: String { case id = "id_field", status = "status_field" }
enum UserStatus: Int { case pending = 0, active = 1 }

let domainDict: [ResponseKey: UserStatus] = [.id: .active]

// Переводим [EnumKey: EnumValue] ➡️ [String: Int]
let apiPayload: [String: Int] = domainDict.resolveRepresentation()
print(apiPayload["id_field"] == 1) // true
```

### 2. Реконструкция из сырых типов в перечисления (Для парсинга DTO)
При обратной конвертации из сырого JSON в доменные модели, система гарантирует безопасность: если бэкенд пришлет невалидный статус или неизвестный ключ, нода будет безопасно отсечена без краша рантайма.

```swift
let rawInput: [String: Int] = ["id_field": 1, "status_field": 99] // 99 — битый статус

// Переводим [String: Int] ➡️ [ResponseKey: UserStatus]
let cleanDomainDict: [ResponseKey: UserStatus] = rawInput.resolveRepresentation()

print(cleanDomainDict[.id] == .active) // true
print(cleanDomainDict[.status] == nil) // Точечно очищено (99 отсеяно), словарь валиден!
```

### 3. Глубокое развертывание опционалов (Stripping Optional Nils)
Специализированные перегрузки умеют одновременно очищать хэш-таблицы от опциональных `nil`-значений и приводить ключи/значения к нужным типам:

```swift
let rawWithNils: [ResponseKey: String?] = [.id: "123", .status: nil]

// Переводим [EnumKey: Value?] ➡️ [String: Value] с вычищением nils
let cleanPayload: [String: String] = rawWithNils.resolveRepresentation()

print(cleanPayload.count == 1) // Нода .status удалена, остался только чистый "id_field"
```

## ⏳ Важное примечание по производительности и компиляции (Compiler Overhead Warning)

**Используйте систему `resolveRepresentation` осознанно и избегайте её вызовов внутри высокочастотных циклов или UI-рендеринга!**

Слово **`resolve`** в названии метода выбрано умышленно, чтобы подчеркнуть тяжесть выполняемой операции. Под капотом системы развернута сложнейшая многоуровневая дженерик-матрица перегрузок, которая заставляет компилятор Swift на этапе сборки совершать тяжелейший поиск цепочек соответствия типов (Type Inference Setup). 

* **Оверхед компиляции**: Нагромождение вложенных вызовов `resolveRepresentation` в одном выражении может кратно увеличить время сборки проекта или привести к ошибке компилятора *"Expression was too complex to be solved in reasonable time"*.
* **Рантайм-оверхед**: Метод полностью перестраивает хэш-таблицу в памяти с выделением новых нод и бакетов. Для горячих путей выполнения (например, скролл списков) кэшируйте результаты разрешения заранее или выполняйте маппинг на фоновом потоке в слое парсинга DTO.
